# Transit Tales

**Transit Tales** is the game title; **TransitTales** is the project identity for this collection of playful transit adventures. The local project folder remains **`D:\my_projects\Lego`**, and the Copilot app’s existing **Lego** registration is retained intentionally. The npm package is named **`transit-tales`** to follow npm’s lowercase naming rules. The GitHub repository is [micwu-personal/TransitTales](https://github.com/micwu-personal/TransitTales). The collection opens in an English / Chinese / Japanese / Cyrillic Mongolian / traditional Mongolian transit concourse connecting **Rush Hour Rescue / 地铁调度室**, **Escalator Orchestra / 扶梯拼拼乐**, **Beijing Journey / 北京出行记** and **Melody Train / 旋律列车**, alongside the preserved original **Build a World** experiment.

Build a World is an original, browser-first 3D building game for children. Make miniature worlds from clay-like shapes, then watch each world respond to what you built. Built with TypeScript, Babylon.js, and Vite. No account, downloads, or external game assets are needed; creations are saved in this browser.

## Run

Requires Node.js 20.19+ or 22.12+.

```sh
npm install
npm run dev
```

Open the local address Vite prints (normally `http://localhost:5173`). `npm run build` makes a production site in `dist/`; `npx vite preview` serves that build. `npm run test` runs the building, transit, localization, and renderer-adapter tests. The original building game requires WebGL; the transit games offer genuine 3D presentation with complete lightweight 2D fallback, so transit gameplay does not require WebGL.

## Melody Train / 旋律列车

Open `/melody.html`, or choose the musical departure in the concourse. Twelve untimed, replayable lessons connect **edit a real score → listen → watch the train → revise**. They introduce the five-line staff, treble/bass/alto/tenor clefs, whole through sixteenth notes, dots, rests, 3/4 and 6/8, sharps/flats/naturals, key signatures and barline accidental resets. Every lesson starts with one approachable wrong note; **Listen to the mission** and the optional target score help without automatically solving it. Checking the corrected score saves completion and offers the next lesson. All lessons are available immediately. A sixteen-event free-composition bench supports undo, remove, reset, key/meter changes and local saving. Keyboard players can select actual staff notes, use up/down to change written pitch, and Delete to remove. Native selectors and named note buttons provide an alternative to reading the drawing.

The scene is an original miniature musical railway, in genuine lazy-loaded Babylon 3D with orbit/zoom/reset or a complete SVG contour view. Switching views/languages preserves the score and playback. It illustrates melodic contour—not five separate tracks, equal diatonic spacing as semitones, or train speed as notation duration. The actual staff remains the notation reference. English, Chinese, Japanese and both Mongolian scripts share the existing saved language; traditional-script prose uses the bundled Mongolian font while music geometry stays horizontal. Translations remain drafts pending native-speaker review.

**Tuning is explicitly A4 = 440 Hz, twelve-tone equal temperament**, using `440 * 2 ** ((midi - 69) / 12)`. WebAudio sine oscillators receive that frequency directly, with detune zero, no vibrato, pitch-shifting or background music. The editor shows resolved frequency to six decimal places; display rounding does not alter synthesis. Quiet finite envelopes reduce clicks. Rests create no oscillator, explicit accidentals apply to the same letter/octave until the next bar, naturals override keys, and the key signature returns at the barline. Tempo means quarter notes/minute even in 6/8. Incomplete drafts may play, but notes crossing a barline require editing; ties are not implemented. Sound starts only from interaction, with volume/mute/stop controls and hidden-tab/exit cancellation.

A separate **Listen & guess** mode practices thirteen chromatic pitches C4–C5 without showing the mystery note, score or frequency before an answer. Replay retains the pitch; a new question avoids the previous pitch. One answer counts per question, followed by the actual note/frequency and optional answer playback. Muted, zero-volume or unavailable audio cannot authorize a guess. This supports stable pitch-reference practice, **not a promise of acquiring absolute pitch**. A4=440 Hz is a common reference, not the only official tuning; device sample clocks, output hardware, headphones/speakers and browser policies limit physical accuracy. Software/offline spectral verification does not certify a device's acoustic output or physical iPad/Safari behavior.

Run `npm test -- --run tests\melody-model.test.ts tests\melody-audio.test.ts tests\melody-journey.test.ts` for notation, all lesson fixtures, localization, saves and audio lifecycle. With Playwright and Chromium/Edge available, `node tests\melody-game.browser.cjs` verifies actual interactions, responsive locales, dual-view state/fallback, 44px scene controls and real OfflineAudioContext pitch rendering; its ephemeral server and browser close afterward. The complete regression passed **620 tests across 38 files** using `npm test -- --maxWorkers=2` (one optional browser test skipped). ## Structure and limits

`src/model.ts` contains portable building rules, missions, validation and history; `src/world.ts` contains Babylon rendering and animation; `src/main.ts` handles the browser UI and localStorage. The web platform boundary leaves room for a future Tauri or mobile shell without including one now. Art is procedural and original; the app uses system fonts plus a locally bundled traditional Mongolian font and can run locally when its files are served from a local server. The full Babylon rendering bundle remains roughly 1.2 MB before compression (about 290 KB compressed); Vite warns about the chunk size, and the recorded metro announcements are bundled with the site rather than fetched from a voice service during gameplay.

### Step inside and hear the city

Click or keyboard-activate a station or train to open an original side-view station/carriage cutaway in a floating, internally scrolling inspector beside or over the city. Dispatch continues while inspecting; pause the shift to linger. Figures reflect actual platform/train passengers (up to 24 drawn, with the remainder counted), not a separate crowd simulation. Central lets you choose either line. Back to the city or Escape closes the view and returns focus.

The broadcast panel provides localized captions, playback status, replay/retry and a persistent mute control. Opening a view starts a recording from the click gesture. Automatic journey changes finish the current sentence before playing the newest pending announcement, even if no further event occurs; stale intermediate announcements are coalesced rather than building a backlog. The main caption stays synchronized with the speaking recording and a separate line shows the queued broadcast. Explicit replay, selection, platform, preview and language changes may replace playback deliberately; mute, closing and page exit clear pending audio. Platform/preview changes start only once. `broadcast.ts` schedules recordings above the low-level player and reuses one media element to retain mobile playback authorization. Browser autoplay restrictions may require tapping Play again. The broadcast studio explicitly labels non-stopping service and other sample scenarios as previews; it does not introduce express services or emergency simulation.

`interior.ts` creates detached frozen interior snapshots and original SVG scenes; `inspector.ts` owns interaction and localized controls. `announcements.ts` separates typed scenario descriptors, localized scripts and recording lookup from `audio.ts` playback lifecycle. Full-sentence English, Mandarin, Japanese and Mongolia Mongolian MP3 recordings ship under `public/audio/transit/`, so voice quality does not depend on installed OS speech voices. Extending or refining broadcasts means adding scripts/contexts and replacing or regenerating assets, not changing simulation rules.

MP3/HTMLAudio is supported by contemporary Windows/macOS/iOS/iPadOS/Android browsers; captions and explicit playback recovery remain available when sound is blocked, a file is unavailable, or a device is silent. This is cross-platform implementation, not certification of every browser/device, nor a guarantee against OS mute, device policy, or network failures. ## Publish on GitHub Pages

The site is live at **https://micwu-personal.github.io/TransitTales/**. Only `micwu-personal/TransitTales` was made public, with explicit authorization, to enable Pages. The workflow `.github/workflows/pages.yml` automatically builds, tests, and deploys every push to **`main`**, including pull-request merges. Other branches and unmerged pull requests do not trigger publication. Deployment runs only after tests and the build succeed; deployments are serialized to avoid overlapping publishes. Manual dispatch remains available for retries or republishing.

1. In `micwu-personal/TransitTales`, open **Settings → Pages**. Pages is already enabled for this public repository; no further visibility change is needed.
2. Set **Build and deployment → Source → GitHub Actions**. Review that a published project site is ordinarily publicly accessible even if its source repository is private; do not publish secrets or private material.
3. Merge a pull request into `main` or push an update to `main`. Open **Actions → Publish Transit Tales** and wait for both build and deployment to succeed. To deploy manually, choose **Run workflow → main**.
4. Open **https://micwu-personal.github.io/TransitTales/**. The Actions build uses `/TransitTales/` as Vite's base so scripts, fonts, recordings and links resolve below the project URL. Normal local development retains `/`.

To host at the account root instead, use a separate repository named `micwu-personal.github.io` and adjust the build base to `/`.
