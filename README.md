# Transit Tales

**Transit Tales** is the game title; **TransitTales** is the project identity for this collection of playful transit adventures. The local project folder remains **`D:\my_projects\Lego`**, and the Copilot app’s existing **Lego** registration is retained intentionally. The npm package is named **`transit-tales`** to follow npm’s lowercase naming rules. The GitHub repository is [micwu-personal/TransitTales](https://github.com/micwu-personal/TransitTales). The collection opens in an English / Chinese / Japanese / Cyrillic Mongolian / traditional Mongolian transit concourse connecting **Rush Hour Rescue / 地铁调度室** and **Escalator Orchestra / 扶梯拼拼乐**, alongside the preserved original **Build a World** experiment.

Build a World is an original, browser-first 3D building game for children. Make miniature worlds from clay-like shapes, then watch each world respond to what you built. Built with TypeScript, Babylon.js, and Vite. No account, downloads, or external game assets are needed; creations are saved in this browser.

## Run

Requires Node.js 20.19+ or 22.12+.

```sh
npm install
npm run dev
```

Open the local address Vite prints (normally `http://localhost:5173`). `npm run build` makes a production site in `dist/`; `npx vite preview` serves that build. `npm run test` runs the building, transit, localization, and renderer-adapter tests. The original building game requires WebGL; both transit games offer genuine 3D presentation with complete SVG 2D fallback, so transit gameplay does not require WebGL.

## Escalator Orchestra / 扶梯拼拼乐

Open `/escalator.html`, or choose the atrium departure from the collection. Fourteen handcrafted puzzles progress from a two-piece café route to branching journeys, wheelchair access, courtyard detours, and balloon headroom, then rooftop lanterns, downward returns, shared trunks, serpentine routes, a garden maze and a combined-access finale. Planning has no timer: choose a short/long escalator, bridge, or elevator, then tap its start and end landings. Each arrow points from the first landing toward the second. Matching endpoints connect; floor lines alone are not walkable routes. Destination symbols and text supplement color.

Select a placed piece to reverse its direction, mirror an escalator, or delete it. Undo, reset, and puzzle-specific hints make experimentation easy. Connected goals show checkmarks and dotted route previews. **Play shoppers** launches a short deterministic wave; pause/resume, return to editing, or replay freely. All shoppers arriving earns two or three stars; using no more pieces than the authored solution earns three. Different destinations arriving together add combo points. Scores and stars are saved per puzzle in this browser only; every puzzle is available without unlocking.

Wheelchair shoppers can only use elevators and level bridges. Solid courtyards block construction; striped physical low roofs and height gauges identify where balloons cannot pass. Waiting figures, prominent independent wheelchair/balloon badges, and route-specific warnings explain needs before departure—even when a shopper has both requirements. Escalator stairs animate for presentation only.

The game opens in a real, rotatable **3D miniature atrium** when WebGL is available. Drag open space to orbit, use **Reset view**, and tap labeled landing buttons to build. **2D plan** provides the complete original SVG game and is selected automatically if 3D fails. Changing views preserves routes and wave state. On phones the 3D scene fits the screen; the 2D plan retains contained horizontal scrolling. `?view=2d` opens directly in the lightweight plan.

**Play calm music** starts an original, gently looping WebAudio arrangement from MIDI-note pitches: mellow chords, soft bell/piano arpeggios, and bass. Music is opt-in, with a volume slider and pause; arrivals add quiet notes. No external music service or copyrighted recording is used. Music fades out and scheduling stops while hidden, and gameplay never depends on audio. Browser autoplay/mute policies still apply.

**Enable round sounds** is separate from calm music and starts off: enable it once from a click/tap to authorize audio. A fully successful wave plays an original short happy flourish exactly once. Successful rounds also show a brief musical-note celebration in both views; reduced motion keeps it static. Unhappy shoppers display concern markers, and the destination list explains the affected shoppers, landings, and missing route, stairs or low-headroom problem. Valid shoppers still travelling are not marked unhappy. Editing and retrying clears the old feedback. Muting, hiding or leaving cancels the flourish without replaying it on return; silent or blocked audio never stops the game.

All five written languages—English, Simplified Chinese, Japanese, Cyrillic Mongolian and traditional Mongolian—switch immediately without clearing the board or wave. The shared language key is `transit-tales-language`; this game's selector is `#escalator-language`. Keyboard players can Tab to tools/landings/pieces and activate with Enter or Space; from outside native controls, Space pauses/resumes, R reverses, M mirrors, Delete removes, and Escape cancels unfinished placement.

`src/escalator/model.ts` owns pure placement geometry, directed routes, history, waves, and scoring; `puzzles.ts` owns puzzle data and verified solutions. `view.ts` creates detached, deeply frozen presentation snapshots. `renderer.ts` and lazy-loaded `renderer3d.ts` share the replaceable `mount/render/dispose` contract. `music.ts` owns deterministic original composition and audio lifecycle; `round-sound.ts` and `round-feedback.ts` independently guard gesture-authorized, once-per-round completion effects. `feedback.ts` and `access.ts` identify affected shoppers and route-specific constraint warnings. `main.ts` handles browser controls, renderer selection, language and scheduling; `storage.ts` validates local best scores. The 3D scene is a genuine presentation renderer, not a physics/crowd simulator or falling-block Tetris. There is no cross-game progress system or real-city importer yet. The escalator tests verify all fourteen solutions, restrictions, geometry, history, deterministic waves—including low-frame-rate quarter-second updates—snapshot isolation, music lifecycle and safe persistence. The complete 254-test suite and TypeScript/Vite build pass; browser gameplay checks complete every solution in the SVG plan and the combined-access finale in real 3D. All five locales were checked at 1440px and 390px: no document overflow, all 28 3D landing controls inside the scene with at least 44px targets, and working phone-sized pointer construction. Production-base checks cover lazy chunks, pointer building, preserved routes, actual synthesized audio output, volume zero, hidden-tab audio recovery and WebGL context-loss fallback. Current feedback checks additionally cover once-only success audio independent of music, enable/mute/hidden lifecycle, failure reasons, correction/retry, and celebrations in both views with all five phone-sized locales. `node tests/escalator-feedback.browser.cjs` runs the bounded Chromium/Edge browser regression using an ephemeral local Vite server, including tablet touch placement, synthetic-click suppression, drag/cancel guards, keyboard activation and renderer cleanup. These emulated checks are not physical iPad/Safari certification. The local upgrades retain the newer 12-second metro segments and 180/195/210-second shifts so the speech scheduler is not dependent on shortened simulation timings.

## Build a World

Choose **Skyline Rescue**, **Wonder Park**, **Pocket Solar System**, **Story Parade**, or **Creative Studio**. Choose a shape in the workbench, then tap/click the stage to place it. You can also drag a shape onto the stage with a mouse. Drag on the stage to look around; scroll or pinch to zoom. Tap/click an existing piece while at Level 1 to select it. Change its color, rotate it, or remove it. Use **+** and **−** to place at different levels; lower back to Level 1 to select again. The mission card shows what to try next. **Test my world** brings the scene to life and gives a hint if it needs more work.

**Keys:** R rotate; Delete/Backspace remove the selected piece; Ctrl/⌘+Z undo; Ctrl/⌘+Shift+Z or Ctrl+Y redo; Escape close a panel or deselect.

Changes are automatically recovered per world. **Save** creates a separate snapshot for the current world; **Load** returns to that snapshot. **Clear** asks before emptying the current world and can be undone. Browser storage is local to this browser/profile and can be lost if site data is cleared; it does not sync or export files.

## Rush Hour Rescue prototype

Open `http://localhost:5173/rush-hour.html` after `npm run dev`. This is a separate, original metro dispatch game; select the Transit Tales brand to return to the collection. The building game remains at `/build-world.html`. Start a shift, select a station on the map, and send a spare train to help its queue. Platform helpers speed up boarding; trains stopped at Central can hold their doors for a connection. Use pause and 1×/2×/3× speed freely. Three short scenarios have replayable goals and local best scores. Space pauses; keys 1–3 select speed. On touch screens the dispatch desk sits below the map. The 3D coastal city fits narrow screens; the 2D map uses contained horizontal scrolling to keep station labels and touch targets readable.

Choose **English**, **简体中文**, **日本語**, **Монгол (Кирилл)** (`mn-Cyrl-MN`), or **ᠮᠣᠩᠭᠣᠯ** (`mn-Mong-CN`) from the visible language selector. All prototype text, station names, notices, controls, results, and accessible labels switch immediately without restarting or pausing a shift. The selection is saved locally under `transit-tales-language`; without a valid saved preference, the first supported browser language preference selects a supported locale (including Chinese regional and Mongolian script preferences); unsupported languages fall back to English. Blocked browser storage does not prevent switching or playing. The building game shares the same language preference; the archived concept gallery retains its original concept descriptions.

All eight transit/elevator concept designs and original SVG illustrations are preserved at `/transit-concepts/`. They remain separate ideas that can later share systems or become connected small games.

`src/rush/locale.ts` supplies typed five-locale dictionaries, substitutions, scenario content, and safe language preferences. The simulation emits language-neutral notice descriptors so existing notices can be translated when switching. `src/rush/model.ts` contains the seeded, fixed-step simulation independently of the UI; `src/rush/main.ts` handles controls, storage and frame scheduling; `style.css` defines the city-led dispatch shell. Network data is separate from scenario rules for future city packs. This prototype uses a fictional ten-station network, aggregate queues, two lines, fixed travel times, and simplified station/segment occupancy. It is not a professional operations simulator, a real-city importer, or live journey advice. Platform waiting contributes to the score; riders waiting over 100 simulated seconds choose another way home. Spare trains refill every 28 seconds up to three. Goals award up to three stars, but shifts never end early in a punitive failure. Best scores are local and do not sync.

### City presentation and renderer seam

Little Bay opens as an original, genuinely **3D miniature coastal city**: planted neighborhoods, dimensional buildings, water, raised tracks, platforms, passenger figures and moving three-car trains. Drag open space to orbit or use **Reset view**. Native station/train buttons open the same live interiors as the map. **2D map** retains the complete 2.5D SVG coastal diorama; `?view=2d` skips 3D loading. Switching views preserves dispatch, time, pause state, selection and ongoing broadcasts. Failed WebGL initialization or context loss returns to 2D without resetting the shift.

- `src/rush/view.ts` adapts the simulation into readonly, deeply frozen and detached snapshots. Stations and trains use normalized presentation coordinates, and trains include stable segment endpoints, bounded progress and heading. Fractional time is a display-only interpolation, disabled when paused, ready, finished or under reduced motion.
- `src/rush/city.ts` owns the coastal scenery and an independently remappable station layout. The adapter never reads the simulation station `x/y` coordinates. Unknown IDs receive a neutral circular fallback; this is an adapter capability, **not an arbitrary-city gameplay feature**.
- `src/rush/renderer.ts` exposes `CityRenderer` with `mount(host, onSelect, onTrainSelect?)`, `render(snapshot)` and `dispose()`, plus the shipped SVG implementation. The renderer only consumes a snapshot and reports station and train selections; it cannot mutate the simulation. Lifecycle cleanup removes listeners and SVG nodes. Main suspends animation on page exit and remounts on browser back/forward-cache restoration.
- `src/rush/renderer3d.ts` is the lazy-loaded Babylon implementation of the same contract, with responsive camera framing, projected native controls and lifecycle cleanup. Both renderers use one snapshot and report selections, never changing simulation rules. The fixed Little Bay scenery still needs replacement/remapping for another city; no arbitrary-city importer, city pack selector, real-world geography or automatic scene generator is included.
- Upcoming transit mini-games should ship both a complete lightweight 2D renderer and an optional genuine 3D renderer behind detached snapshots and `mount/render/dispose`. Both must preserve gameplay during switches, offer keyboard/touch interaction, respect reduced motion, and fall back safely when WebGL fails.

The 3D camera fits desktop and phone-sized scenes. The 2D city viewport scrolls horizontally below 680px rather than shrinking labels beyond usefulness; all dispatch actions remain available. Language selector QA hook: `#language` (`en` / `zh-CN` / `ja` / `mn-Cyrl-MN` / `mn-Mong-CN`), storage key `transit-tales-language`; renderer SVG: `#map`, contained in `#city-map`.

`npm test -- tests/rush.test.ts` validates routes, dispatch actions, cooldowns, boarding, connections, complete scenarios, and passenger conservation. `tests/rush-locale.test.ts` covers language completeness, substitutions, safe preferences and state-preserving switching. `tests/rush-view.test.ts` covers snapshot immutability, bounded interpolation, frozen states, network independence and multilingual geometry preservation. `npm run build` includes the collection hub, both transit games, the preserved construction page, and the concept gallery.

## Structure and limits

`src/model.ts` contains portable building rules, missions, validation and history; `src/world.ts` contains Babylon rendering and animation; `src/main.ts` handles the browser UI and localStorage. The web platform boundary leaves room for a future Tauri or mobile shell without including one now. Art is procedural and original; the app uses system fonts plus a locally bundled traditional Mongolian font and can run locally when its files are served from a local server. The full Babylon rendering bundle remains roughly 1.2 MB before compression (about 290 KB compressed); Vite warns about the chunk size, and the recorded metro announcements are bundled with the site rather than fetched from a voice service during gameplay.

### Step inside and hear the city

Click or keyboard-activate a station or train to open an original side-view station/carriage cutaway below the city. Dispatch continues while inspecting; pause the shift to linger. Figures reflect actual platform/train passengers (up to 24 drawn, with the remainder counted), not a separate crowd simulation. Central lets you choose either line. Back to the city or Escape closes the view and returns focus.

The broadcast panel provides localized captions, playback status, replay/retry and a persistent mute control. Opening a view starts a recording from the click gesture. Automatic journey changes finish the current sentence before playing the newest pending announcement, even if no further event occurs; stale intermediate announcements are coalesced rather than building a backlog. The main caption stays synchronized with the speaking recording and a separate line shows the queued broadcast. Explicit replay, selection, platform, preview and language changes may replace playback deliberately; mute, closing and page exit clear pending audio. Platform/preview changes start only once. `broadcast.ts` schedules recordings above the low-level player and reuses one media element to retain mobile playback authorization. Browser autoplay restrictions may require tapping Play again. The broadcast studio explicitly labels non-stopping service and other sample scenarios as previews; it does not introduce express services or emergency simulation.

`interior.ts` creates detached frozen interior snapshots and original SVG scenes; `inspector.ts` owns interaction and localized controls. `announcements.ts` separates typed scenario descriptors, localized scripts and recording lookup from `audio.ts` playback lifecycle. Full-sentence English, Mandarin, Japanese and Mongolia Mongolian MP3 recordings ship under `public/audio/transit/`, so voice quality does not depend on installed OS speech voices. Extending or refining broadcasts means adding scripts/contexts and replacing or regenerating assets, not changing simulation rules.

MP3/HTMLAudio is supported by contemporary Windows/macOS/iOS/iPadOS/Android browsers; captions and explicit playback recovery remain available when sound is blocked, a file is unavailable, or a device is silent. This is cross-platform implementation, not certification of every browser/device, nor a guarantee against OS mute, device policy, or network failures. Offline use requires the deployed site and recordings to be available locally; no service-worker offline cache or packaged native app is included.

Recording maintenance: `python scripts\generate-announcements.py` verifies/reuses unchanged assets and regenerates changed scripts; `--force` replaces all recordings. Generation requires edge-tts and ffprobe and sends only the original announcement text to the speech service. The checked-in assets need neither tool nor the voice service at runtime. `manifest.json` records each sentence, voice, byte length and verified duration. The catalog includes 216 verified recordings: 54 each for English, Mandarin, Japanese and Mongolia Mongolian. Both written Mongolian locales share the Mongolia recordings; manifest metadata distinguishes captions from spoken text.

Current integrated validation: all 254 automated tests and the TypeScript/Vite production build pass, including the `/TransitTales/` deployment base. Windows Edge checks cover natural MP3 completion followed by the newest queued recording without another event, one reused media element, single platform/preview playback, language replacement, mute and close. Metro 3D passes all five languages at desktop/mobile sizes (1440px / 390px), visible ≥44px station/train targets, keyboard interaction, preserved paused shifts, WebGL creation/context-loss fallback, and no page overflow or runtime errors. Production checks cover lazy chunks, MP3 access, uninterrupted broadcasts across view changes, back/forward-cache remount, and delayed-import races. Physical Apple/Android devices remain untested.

## Publish on GitHub Pages

The site is live at **https://micwu-personal.github.io/TransitTales/**. Only `micwu-personal/TransitTales` was made public, with explicit authorization, to enable Pages. The workflow `.github/workflows/pages.yml` builds and tests the site, uploads `dist`, and deploys on **manual dispatch only**. Pushing updates alone does not republish the site.

1. In `micwu-personal/TransitTales`, open **Settings → Pages**. Pages is already enabled for this public repository; no further visibility change is needed.
2. Set **Build and deployment → Source → GitHub Actions**. Review that a published project site is ordinarily publicly accessible even if its source repository is private; do not publish secrets or private material.
3. Open **Actions → Publish Transit Tales → Run workflow**, choose `main`, and run it. Wait for both build and deployment to succeed.
4. Open **https://micwu-personal.github.io/TransitTales/**. The Actions build uses `/TransitTales/` as Vite's base so scripts, fonts, recordings and links resolve below the project URL. Normal local development retains `/`.

For automatic updates, add a `push` trigger limited to `main` after opting into publishing. To host at the account root instead, use a separate repository named `micwu-personal.github.io` and adjust the build base to `/`.
